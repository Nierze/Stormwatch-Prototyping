## 1. Overview

**Stormwatch** is a computer-vision-based flood depth estimation system. It uses:

- **YOLOv11 (Ultralytics)** — to segment the flood region within an image.
- **Metric3D** — to generate surface normal maps that act as a depth proxy.
- **Gradio** — as the web-based user interface for both apps.

The system works by:
1. Detecting flooded areas in an image using YOLO segmentation.
2. Overlaying the flood mask onto a surface normal/depth map.
3. Measuring how much of a vertical structure (e.g., a wall) is submerged.
4. Calculating a **relative flood depth** and classifying severity as **Low**, **Medium**, or **High**.

### App Comparison

| Feature | `flood_surface_app_wAPI.py` | `stormwatch_setup_app.py` |
|---|---|---|
| Input Method | Manual image upload | Live camera capture |
| Surface Map | User-uploaded | Auto-generated via Metric3D |
| API Reporting | ✅ Yes | ❌ No |
| Ground Truth System | ❌ No | ✅ Yes (baseline capture) |
| Confidence Threshold Slider | ✅ Yes | ❌ No |
| Best for | Lab/offline testing | Deployed camera hardware |

## 2. System Requirements

### Hardware

- **CPU:** Any modern x86-64 processor (Intel/AMD). ARM (Raspberry Pi) is supported but slow.
- **RAM:** Minimum 8 GB. 16 GB recommended when running Metric3D.
- **GPU:** Optional but recommended. CPU-only mode is supported.
- **Camera:** Any USB/V4L2 webcam (required for `stormwatch_setup_app.py` only).
- **Storage:** ~5 GB free space for model checkpoints.

### Software

- **Operating System:** Windows 10/11, Ubuntu 20.04+, or Raspberry Pi OS (Bullseye/Bookworm)
- **Python:** 3.9, 3.10, or 3.11 (3.12+ not tested)
- **Git:** For cloning the repository
- **Internet connection:** Required on first run of `stormwatch_setup_app.py` to download the Metric3D checkpoint (~1.5 GB)

## 3. Installation

### Step 1: Clone the Repository

```bash
git clone https://github.com/your-org/Stormwatch-Prototyping.git
cd Stormwatch-Prototyping
```

### Step 2: Create a Virtual Environment

```bash
# Windows
python -m venv .venv
.venv\Scripts\activate

# Linux / macOS
python3 -m venv .venv
source .venv/bin/activate
```

### Step 3: Install Dependencies

```bash
pip install -r requirements.txt
```

> **Note:** `mmcv-lite` may require a specific build depending on your CUDA/CPU version. If install fails, try: `pip install mmcv==2.1.0`

### Step 4: Install Metric3D (for stormwatch_setup_app.py only)

The `stormwatch_setup_app.py` depends on the Metric3D submodule located at `models/Metric3D/`.

Ensure the submodule is initialized:

```bash
git submodule update --init --recursive
```

If `models/Metric3D/` is empty after this, manually clone it:

```bash
cd models
git clone https://github.com/YvanYin/Metric3D.git
cd ..
```

### Step 5: Place Your YOLO Model

Copy your trained YOLO segmentation model (`.pt` file) into:

```
deployment models/best.pt
```

This is the **default path** used by `stormwatch_setup_app.py`. For `flood_surface_app_wAPI.py`, you enter the model path manually in the UI.

### Step 6: Metric3D Checkpoint (Auto-downloaded)

When you first run `stormwatch_setup_app.py`, it will automatically download:

- **File:** `metric_depth_vit_large_800k.pth` (~1.5 GB)
- **Saved to:** `~/.cache/torch/hub/checkpoints/`

Ensure you have a stable internet connection the first time. Subsequent runs use the cached file.

## 5. App 1: `flood_surface_app_wAPI.py`

### Purpose

This is the **primary analysis tool** for offline/lab use. You manually upload:
1. A **flood image** (the scene you want to analyze).
2. A **surface/depth map** (a surface normal visualization or depth image for that same scene).

The app runs YOLO segmentation, analyzes flood depth using the surface map, and **sends a structured report to an external API**.

### How to Run

```bash
# From the project root with .venv activated
python apps/flood_surface_app_wAPI.py
```

Then open your browser and navigate to: **http://localhost:7860**

The server also binds to `0.0.0.0`, so it is accessible from other devices on your local network at `http://<your-ip>:7860`.

---

### User Interface Walkthrough

The interface is split into two columns: **Inputs (Left)** and **Outputs (Right)**.

#### Left Column — Inputs

**Image Inputs:**

| Control | Description |
|---|---|
| `Flood Image` | Upload the RGB photo of the flood scene. |
| `Surface/Depth Map` | Upload the corresponding surface normal or depth map. Dark areas = ground/surface. |

**Model Configuration:**

| Control | Type | Default | Description |
|---|---|---|---|
| `YOLO Model Path` | Text | *(empty)* | Full path to your `.pt` YOLO segmentation model. |
| `Detection Confidence Threshold` | Slider 0.05–1.0 | `0.25` | Minimum confidence for YOLO to detect a flood region. Lower = more detections, higher = stricter. |
| `Surface Brightness Cutoff` | Slider 0.0–1.0 | `0.05` | Pixels in the depth map darker than this value are classified as **ground/surface**. Brighter pixels are **structures**. |
| `Critical Area Expansion (px)` | Slider 0–50 | `7` | Dilation applied to the structure mask. Expands the "flood on structure" region to account for edge blur. |
| `Min Vertical Structure Width (px)` | Slider 1–20 | `3` | Minimum horizontal width (in pixels) a detected structure column must have to be considered for the depth measurement line. Filters noise. |
| `Deep Flood Threshold` | Slider 0.1–1.0 | `0.30` | The relative depth ratio above which flood is classified as **High** severity. Values below 10% are **Low**; between 10% and this value is **Medium**. |
| `Depth Source Channel` | Dropdown | `Green` | Which color channel of the surface map to use as the depth signal. Green (Y-axis normals) is typically best for Metric3D output. |
| `Invert Depth Input` | Checkbox | `False` | Reverses depth values (0→1, 1→0). Use if your surface map has opposite depth convention. |

**API Configuration:**

| Control | Default | Description |
|---|---|---|
| `API Key` | `sk_1768192573271_2bhobz0gvp7` | Bearer token for authenticating with the Stormwatch API. |
| `API URL` | `https://api.stormwatch.app/v1/readings` | Endpoint to POST flood readings to. |

#### Right Column — Outputs

| Output | Description |
|---|---|
| `Estimation Result` | The surface map with color overlays: **Green** = flood on ground, **Black** = flood on structure, **Red line** = the deepest measured vertical column. |
| `Flood - Depth Only` | The surface map masked to only show pixels within the detected flood region. Useful for debugging channel selection. |
| `Statistics & API Status` | Text report showing Severity, Max Vertical Interaction (px), Flood Vertical Span (px), Relative Depth (%), and the API response. |

---

### Step-by-Step Usage

1. **Start the app** and open `http://localhost:7860`.
2. **Upload your flood image** in the `Flood Image` box.
3. **Upload the matching surface map** in the `Surface/Depth Map` box.
   - This should be a Metric3D surface normal visualization, or any depth map where brightness correlates with structure height.
4. **Enter the path to your YOLO model** in the `YOLO Model Path` field, e.g.: `D:/models/best.pt`
5. **Adjust sliders** if needed (defaults work for Metric3D normal maps with the Green channel).
6. **Enter your API Key and URL** if you want to report to the Stormwatch backend.
7. Click **"Estimate Flood & Send API Report"**.
8. Review results in the right column.

---

### Output Interpretation

#### Color Coding on the Estimation Result

- 🟩 **Green overlay** — Flood water is covering the **ground/flat surface**. This is the shallow zone.
- ⬛ **Black overlay** — Flood water is covering a **vertical structure** (wall, pole, post). This is the key signal for depth.
- 🔴 **Red vertical line** — The single longest column of "flood on structure" pixels. Its length relative to the overall flood height determines severity.

#### Statistics Box

```
Flood Severity Analysis:

Severity: MEDIUM
Max Vertical Interaction: 142 px
Flood Vertical Span: 480 px
Relative Depth: 29.6%
(Length of red line relative to flood height)

API Success: Reading ID abc123
```

| Metric | Meaning |
|---|---|
| **Severity** | LOW / MEDIUM / HIGH based on relative depth thresholds |
| **Max Vertical Interaction** | Length in pixels of the red measurement line |
| **Flood Vertical Span** | Total vertical pixel span of the detected flood mask |
| **Relative Depth** | `Max Vertical / Flood Vertical Span × 100%` |

#### Severity Thresholds

| Relative Depth | Severity |
|---|---|
| < 10% | **LOW** — Water is shallow, mostly on ground |
| 10% – Deep Threshold | **MEDIUM** — Water is rising against structures |
| ≥ Deep Threshold | **HIGH** — Deep flood, significant structure submersion |

## 6. App 2: `stormwatch_setup_app.py`

### Purpose

This is the **deployed hardware tool** designed for use with a connected webcam. It replaces manual image uploading with a fully automated pipeline:

1. **Setup Phase:** Capture a dry-scene baseline. Metric3D generates and saves a **Surface Normal Ground Truth** map.
2. **Estimation Phase:** Capture a live flood image. Use the saved ground truth as the depth reference to estimate flood severity.

This app is ideal for a Raspberry Pi or edge device with a mounted camera looking at a fixed scene.

### How to Run

```bash
python apps/stormwatch_setup_app.py
```

Then open: **http://localhost:7860**

> **Important:** Metric3D will be loaded on first use. This requires ~4–8 GB of RAM and takes **several minutes** on CPU. A GPU is strongly recommended.

---

### User Interface Walkthrough

The app has **two tabs**.

---

#### Tab 1: Setup Surface Ground Truth

**Purpose:** Capture and save a baseline surface normal map of the scene **before any flooding occurs**.

| Control | Description |
|---|---|
| `Setup Surface Ground Truth` (button) | Captures an image from the camera → runs Metric3D inference → saves the result as the Ground Truth. |
| `Retrieve Current Ground Truth` (button) | Loads and displays the previously saved Ground Truth without recapturing. |
| `Ground Truth Result` | Displays the generated surface normal map. |
| `Status` | Shows success or error messages. |

**How to use:**
1. Point the camera at the scene you want to monitor (ensure it is **dry and unobstructed**).
2. Click **"Setup Surface Ground Truth"**.
3. Wait for the camera warm-up (5 frames × 0.2s = ~1 second) and Metric3D inference (may take 1–5 minutes on CPU).
4. Confirm the Ground Truth image looks correct — it should be a colorful normal map showing surface geometry.
5. The file is saved to: `Ground truth/surface_normal_gt.png`

> ⚠️ **You must complete Setup before running Estimation.** The Estimation tab will error if no Ground Truth file exists.

---

#### Tab 2: Estimate Flood

**Purpose:** Capture a live image during a flood event and estimate flood severity against the saved baseline.

**Flood Configuration (Accordion — collapsed by default):**

| Control | Default | Description |
|---|---|---|
| `Depth Source Channel` | `Green` | Channel of the surface map to analyze. |
| `Invert Depth Input` | `False` | Reverses depth polarity if needed. |
| `Structure Threshold` | `0.05` | Brightness cutoff to separate ground from structures. |
| `Black Expansion (px)` | `7` | Dilation of the structure mask. |
| `Min Width (px)` | `3` | Minimum structure column width. |
| `Deep Threshold` | `0.30` | Relative depth ratio for HIGH severity classification. |

**Outputs:**

| Output | Description |
|---|---|
| `Original Capture` | The raw image captured from the camera. |
| `Flood Overlay` | Annotated image with green/black/red overlays. |
| `Masked Depth` | Surface map restricted to the flood region. |
| `Analysis Info` | Severity, max vertical depth in px, and relative depth %. |

**How to use:**
1. Ensure Setup has been completed (Ground Truth exists).
2. When flooding occurs, navigate to the **Estimate Flood** tab.
3. Optionally expand **Flood Configuration** to tune parameters.
4. Click **"Estimate Flood"**.
5. The app captures a frame, runs YOLO segmentation, and computes flood depth against the saved Ground Truth.
6. Review the three output images and the Analysis Info text box.

---

### Camera Behavior

- The app tries camera indices `[0, 1, -1]` with backends `CAP_ANY` and `CAP_V4L2`.
- It **warms up** by capturing 5 frames (with 0.2s delay each) to let auto-exposure stabilize.
- The captured frame is **flipped 180°** (`cv2.flip(frame, -1)`) — this corrects for cameras mounted upside-down.
- If no camera is found, the app returns: `"Error: No camera found."`

## 7. Configuration Reference

### YOLO Model

Both apps use an Ultralytics YOLO segmentation model (`.pt` format, YOLOv8/v11 series).

- Must be a **segmentation model** (not detection-only). The app specifically checks `results[0].masks`.
- Default expected path for `stormwatch_setup_app.py`: `deployment models/best.pt`
- For `flood_surface_app_wAPI.py`: enter any absolute or relative path in the UI.
- Models are **cached globally** — if you re-run with the same path, it won't reload from disk.

### Metric3D Model

Used only by `stormwatch_setup_app.py`.

| Setting | Value |
|---|---|
| Architecture | ViT-Large with RAFT decoder |
| Config file | `models/Metric3D/mono/configs/HourglassDecoder/vit.raft5.large.py` |
| Checkpoint | `metric_depth_vit_large_800k.pth` |
| Download URL | HuggingFace JUGGHM/Metric3D |
| Cache location | `~/.cache/torch/hub/checkpoints/` |
| Device | CPU (set via `DEVICE = "cpu"`) |

To switch to GPU, change line 30 in `stormwatch_setup_app.py`:
```python
DEVICE = "cuda"  # or "mps" for Apple Silicon
```

### Default Camera Intrinsics

Metric3D requires camera intrinsics. Since no calibration is performed, defaults are used:
```python
intrinsic = [1000.0, 1000.0, w / 2, h / 2]
# [focal_x, focal_y, principal_x, principal_y]
```
For better accuracy with a calibrated camera, replace these with your camera's actual intrinsics.

## 8. API Integration

Applies to: **`flood_surface_app_wAPI.py`** only.

### Payload Schema

Every time you click "Estimate Flood & Send API Report", the app sends an HTTP POST:

```json
{
  "readingType": "water_level",
  "value": 29.6,
  "unit": "%",
  "metadata": {
    "status": "MEDIUM",
    "sensor_id": "STORMWATCH_CAM_01",
    "max_vertical_px": 142,
    "timestamp": "2026-05-14T21:00:00.000000"
  }
}
```

| Field | Description |
|---|---|
| `value` | Relative flood height as a percentage (0–100) |
| `metadata.status` | `LOW`, `MEDIUM`, or `HIGH` |
| `metadata.sensor_id` | Fixed identifier `STORMWATCH_CAM_01` |
| `metadata.max_vertical_px` | Raw pixel length of the red measurement line |
| `metadata.timestamp` | ISO 8601 timestamp of the analysis |

### Authentication

The API uses **Bearer token** authentication:

```
Authorization: Bearer <your-api-key>
```

Enter your API key in the `API Key` field in the UI.

### Response Handling

| HTTP Status | Behavior |
|---|---|
| `200` or `201` | Shows `"API Success: Reading ID <id>"` |
| Any other | Shows `"API Failed (<status>): <response body>"` |
| Network error | Shows `"API Error: <exception message>"` |

> **Note:** If flood is not detected (no YOLO masks), the app still sends an API report with `value: 0.0` and `status: LOW`.

## 9. Troubleshooting

### App won't start

| Symptom | Fix |
|---|---|
| `ModuleNotFoundError: No module named 'gradio'` | Run `pip install -r requirements.txt` with your venv active. |
| `ModuleNotFoundError: No module named 'mono'` | Metric3D submodule is missing. Run `git submodule update --init --recursive`. |
| `ModuleNotFoundError: No module named 'mmcv'` | Run `pip install mmcv-lite` or `pip install mmengine`. |

### YOLO Model Issues

| Symptom | Fix |
|---|---|
| `Model not loaded. Failed to load from: ...` | Check that the path is correct and the file exists. Use the full absolute path. |
| `No flood detected.` | Lower the `Detection Confidence Threshold` slider. The model may be too strict. |
| YOLO loads but produces wrong masks | Ensure the model is a **segmentation** model, not a detection-only model. |

### Camera Issues (stormwatch_setup_app.py)

| Symptom | Fix |
|---|---|
| `Error: No camera found.` | Check USB connection. Try a different index by editing line 159: `indices = [0, 1, 2]`. |
| `Error: Failed to capture frames.` | Camera opens but can't read. Check permissions (`ls /dev/video*` on Linux). |
| Image appears upside-down after fixing the flip | Remove or change the `cv2.flip(frame, -1)` on line 194 to `cv2.flip(frame, 0)` or `cv2.flip(frame, 1)`. |

### Metric3D Issues

| Symptom | Fix |
|---|---|
| Download fails or hangs | Manually download `metric_depth_vit_large_800k.pth` from HuggingFace and place in `~/.cache/torch/hub/checkpoints/`. |
| Out of memory (OOM) during inference | This model is large. Close other applications. Reduce image resolution before capture. |
| Inference takes very long | Expected on CPU (~5–15 min). Switch `DEVICE = "cuda"` if GPU is available. |
| `NaN` in surface normal output | The code auto-handles this with `np.nan_to_num`. If the output is all black, the capture may be corrupt — try recapturing. |

### API Issues

| Symptom | Fix |
|---|---|
| `API Failed (401)` | Check your API Key. It may be expired or incorrect. |
| `API Failed (404)` | Verify the API URL is correct. |
| `API Error: Connection refused` | The server is unreachable. Check internet connection or server status. |

## 10. Tips & Best Practices

### For Best Depth Estimation Results

- **Use Metric3D output** as the surface map — it is what the system was designed for.
- **Green channel** is generally the best depth proxy for Metric3D surface normals (encodes Y-axis / vertical orientation).
- If your scene has no clear vertical structures, the red line may not appear and severity will always be Low.
- **Calibrate the Deep Threshold** for your specific scene and camera angle. A scene with a short wall needs a lower threshold than one with a tall building.

### Camera Placement (stormwatch_setup_app.py)

- Mount the camera at a **fixed angle** — do not move it after setup.
- Ensure the camera has a **clear, unobstructed view** of both the ground surface and a vertical reference structure (e.g., a wall, pole, or post).
- Capture the **Ground Truth on a dry day** with consistent lighting.
- Avoid strong shadows or reflections that can confuse the YOLO segmentation.

### Running Setup Again

Re-running **"Setup Surface Ground Truth"** will **overwrite** the existing `Ground truth/surface_normal_gt.png`. Only do this if the camera has been repositioned or the scene has changed significantly. Otherwise, the old ground truth is still valid.

### Model Caching

Both apps cache the YOLO model in memory after the first load. If you switch model paths, the new model will load automatically. You do **not** need to restart the app.

### Running in the Background (Linux/Raspberry Pi)

```bash
# Run detached from terminal using nohup
nohup python apps/stormwatch_setup_app.py > stormwatch.log 2>&1 &

# Or with screen
screen -S stormwatch
python apps/stormwatch_setup_app.py
# Ctrl+A, D to detach
```

### Accessing Remotely

Both apps bind to `0.0.0.0` (all interfaces). From another device on the same network:

```
http://<host-ip>:7860
```

Find your host IP with `ipconfig` (Windows) or `hostname -I` (Linux).
